# Como trabalhar com Issues

Uma Issue registra o problema antes do código. Ela dá contexto e permite confirmar quando a tarefa terminou.

1. Procure se já existe uma Issue para o trabalho.
2. Leia contexto, tarefa e critérios de aceite.
3. Escreva dúvidas antes de implementar.
4. Atribua a Issue a você, se esse for o processo da equipe.
5. Cite `#número` no PR e use `Closes #número` se ele resolver a Issue.

Transforme cada critério em uma verificação. Se o requisito mudar, registre a decisão na Issue. Não aumente o escopo silenciosamente.

Use os templates de tarefa de estudo, feature ou bug ao criar uma Issue.
